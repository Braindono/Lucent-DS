This is an original system, built from scratch rather than pulled from an existing brand — there was no codebase, deck or guideline set to source from, so every value below is a deliberate first-round decision, not an extraction. It exists to be **purpose-agnostic**: the same tokens and surface language need to hold up in a responsive web app, a native mobile/tablet OS surface, a styled presentation or document, and a mixed-reality spatial panel, without knowing in advance which of those it will render in.

**The direction is locked.** `Primary Direction` (under Primary Direction, above) is Lucent's shipping identity — a merge of `Concept A — Instrument`'s structure and restraint with `Concept B — Atrium`'s glass, carrying a locked `accent-primary`/`accent-secondary`/`accent-tertiary` hierarchy (indigo/violet/cyan) instead of one accent per concept. `Concept A — Instrument`, `Concept B — Atrium` and `Concept C — Aurora Console` — spanning brutalist restraint to opulent maximalism — remain below as the exploration this direction came from; they still share every token in this file, and their own single-accent conventions (`accent-a`/`accent-b`/`accent-c`) are untouched. Open any card, toggle it between light and dark with its own switch.

## Content fundamentals

Write UI labels short and declarative, Title Case for controls and nav ("Save Layout", not "save layout" or "Save Layout!"). Write body and helper copy in sentence case, calm and precise — no exclamation points, no "Oops!" error tone; an error states what happened and what to do about it. Render every number, unit, coordinate, timestamp or version string in `data-mono`, never in the sans body face — numerals in a geometric sans wobble in weight at small sizes, and a monospace readout is part of the instrument-panel identity this system borrows from hardware design. Set instrument-style tags and tick labels in `label-mono`, uppercase, set in CSS rather than typed in caps.

## Type scale

Every font-size and line-height in the Display/Heading/Text/Label groups is expressed in `rem`, not `px` — the scale resolves against the root font-size, so it moves as one unit if the root changes. This is what makes a user-facing text-scale control possible; that control itself (a stepper adjusting root size) is scoped but not yet built — see TODO.md.

## Visual foundations

**Elevation is shadow, not color.** `surface-base`, `surface-raised` and `surface-sunken` all resolve to the same value in a given theme — the classic neumorphic discipline of one ambient surface color throughout. Depth comes only from `shadow.neu-raised` (an embossed dual shadow: a soft dark shadow to the lower-right, a soft light highlight to the upper-left) on raised elements — buttons, dials, switches at rest — and `shadow.neu-inset` (the same pair, inverted) on sunken ones — wells, track grooves, pressed states. Never fake elevation with a lighter or darker fill; that reads as a second surface color, not as light falling on one surface.

**Glass sits above the neumorphic base, never replaces it.** A glass panel is `glass-surface` or `glass-surface-strong` with `backdrop-filter: blur()` at `blur-sm/md/lg`, a 1px `glass-border` on its top and left edge only (the edge catching light, not a boxed-in outline on all four sides), and a `glass-highlight` gradient line tracing that same top edge. Stack glass panels on `glass-elevation-1/2/3` to build a parallax field: the plane nearest the viewer gets `glass-elevation-3` and the most blur, the plane resting on the neumorphic base gets `glass-elevation-1` or none. On scroll or pointer movement, shift each plane by a different amount (more for near planes, little to none for the base) rather than moving the whole composition as one flat layer — that differential motion is what reads as 3D, not the blur alone.

**Color carries identity, not decoration.** `ink-*` and the `surface-*`/`glass-*` neutrals do the structural work everywhere. Each exploration concept claims exactly one accent track — `accent-a` (indigo, Instrument), `accent-b` (cyan, Atrium) or `accent-c` (violet, Aurora Console) — and spends it on the one or two elements that most need attention: a primary action, an active state, a live readout. The locked Primary Direction and the panel case study instead share one three-step hierarchy across the same three hues: `accent-primary` (indigo), `accent-secondary` (violet) and `accent-tertiary` (cyan) — primary for the main action and any state that's "on," secondary for a live delta or an outlined second action, tertiary for a small status tell only (a dot, a tag), never a solid fill or body text; the same restraint `accent-b` and `accent-c-glow` already used. `accent-c-glow` (`violet-500`) is the one color token restricted to decorative use — large icons, borders, edge-glow — because at normal text size on this system's surfaces it falls under the 4.5:1 floor; `accent-c`/`accent-secondary` (`violet-700`) is what carries button labels and small text instead. `focus-ring` is deliberately its own color, independent of any accent, so a focused control is never mistaken for an accent-colored one.

**`ink-faint` is never text.** It measures 2.01:1 on the light surface and 2.48:1 on the dark one, which fails WCAG AA for text at any size. Use it only for borders, dividers, icons, and non-text fills such as toggle knobs and swatches. Captions, hints, footers, axis labels, timestamps and placeholders use `ink-muted`, which passes AA in both themes. This covers SVG `fill` on `<text>` too. (a11y pass 2026-09-25)

**Radius encodes the brutalist-to-maximalist spread.** `radius-xs`/`radius-sm` (4–8px) belong to Instrument's sharper, more restrained geometry; `radius-md`/`radius-lg` (14–24px) carry Atrium's generous, iOS/macOS-adjacent roundness; `radius-lg`/`radius-xl`/`radius-full` (24px–a full disc) carry Aurora Console's pills, dials and circular readouts. All three concepts draw from the same six-step scale — none has its own private radius tokens — because the point of the exploration is to see where on one continuous scale the final system should sit.

**Layout is a 4px grid with no fixed breakpoint list.** Every `space-*` token is a multiple of `space-1` (4px). Because this system has to reflow from a wrist- or phone-scale surface up to a spatial panel with no single target in mind, lay components out with fluid sizing (`clamp()`, `minmax()`, container queries where available) rather than a named set of breakpoints; a component should look intentional at any width, not just at a handful of tested ones.

**Case studies apply this system to real products, and can extend it.** One case study (not included in this release) is a style guide rebuilt entirely on Lucent tokens — proof this system holds up outside its own concepts. Structural tokens that were genuinely general-purpose graduated from that case study into the shared set: `radius-squircle` (a percentage superellipse radius) and `status-info` (a reserved color for activity states, distinct from the good/warning/serious/critical severity ladder). Its accent hierarchy graduated too, in the other direction: the panel case study's Primary/Secondary/Tertiary hues are `accent-primary`/`accent-secondary`/`accent-tertiary`, the same locked triad the Primary Direction component uses — an early version of the panel case study's tertiary used a one-off green invented only for that case study, which sat too close to `status-good` and didn't come from anywhere else in the system; it's since been replaced with `accent-tertiary`. What's still scoped to the panel case study alone is its own three font families and its local Primary=violet/Secondary=indigo ordering; none of that changes what Concepts A/B/C, the Dashboard, or the Primary Direction use.

**Data visualization has its own reserved tokens.** Chart marks — lines, bars, dots — use `viz-series-a/b/c` (indigo, cyan, violet), not the raw hue swatches or the concept accents directly: the `viz-series-*` set is the specific step of each hue validated to sit in the categorical lightness/chroma band on `surface-base` in both themes. `viz-series-b` (cyan) sits below 3:1 in light theme by design — always ship it with a legend or direct labels, never as an unlabeled fill alone. State — good, warning, serious, critical — uses `status-good/warning/serious/critical` and nothing else; a status color always carries an icon and a label, never hue alone, and a series that IS a status (an error count, a pass/fail rate) wears status tokens rather than a `viz-series-*` slot. Sequential magnitude (a heatmap, a density field) stays one hue, light to dark — vary `viz-series-c`'s opacity rather than introducing a second hue.

## Motion

Motion is a closed set: one easing curve (`ease-out`, `cubic-bezier(0.22,1,0.36,1)`) and two durations (`dur-fast`, 120ms, for press/tap feedback only; `dur-base`, 180ms, for everything else — panel reveals, glass-surface entrances, hover states). There is deliberately no slower duration and no spring or bounce physics; motion in this system confirms an interaction, it never performs one. Every transition or animation in a component must reference these three tokens rather than an ad hoc value, and every one of them is wrapped in `@media (prefers-reduced-motion: reduce)`, disabled or sharply shortened there — nothing in Lucent is load-bearing for comprehension. The one named exception is `status-pulse` (opacity 1 → .35 → 1), reserved for `status-info`'s "active/in-progress" state so it reads as distinct from a static severity dot; it is not a general-purpose attention device.

## Iconography

The icon set is `project/icons/` — 1,383 single-ink outline icons (`viewBox="0 0 24 24"`, `stroke="currentColor"`, `stroke-width: 1.5`, `fill: none`), delivered as one sprite (`icon-sprite.svg`, a `display:none` wrapper of `<symbol id="...">` defs) plus a structured `manifest.json` and a flat `index.txt` for fast grep lookup. Source: an original asset of this project (no third-party library). Use one ink token per icon via `currentColor` — set `color` on the `<svg>`/`<use>` wrapper, never per-path — matching the single-ink rule concept-stage controls already followed with plain geometric shapes. See `project/icons/README.md` for the lookup workflow and the Core-UI shortlist (menu, close, external-link, directional arrows, search, socials, mail) covering near-term component needs. It's registered in `project/design-system.json` under `iconSets.lucent-icons`, not just dropped in the folder.

## The three concepts

**Concept A — Instrument.** The brutalist end: mostly bare neumorphic surface, sharp `radius-xs`/`sm`, a single indigo accent spent on one primary action, mono tick labels and a visible structural grid — closer to a piece of measuring hardware than a piece of glass. Glass appears once, as a small frosted tag, to prove the hybrid without softening the whole panel.

**Concept B — Atrium.** The balanced middle, closest to current iOS/macOS glass language pushed further: layered frosted panels over a soft neumorphic base, generous `radius-md`/`lg`, a cyan accent, and a slow parallax wash of light behind the glass. This is the safest of the three to ship broadly.

**Concept C — Aurora Console.** The maximalist end: dense layered glass with visible depth, glowing violet-and-cyan edges, large pills and discs, bold mono readouts — a retro-futurist control console rather than a flat app screen. Busiest of the three; judge it on whether the density stays legible, not on restraint.
